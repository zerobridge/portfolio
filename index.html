실무

롯데GRS AI 챗봇 - 수치 할루시네이션 차단 아키텍처 설계

LLM/RAG, AI Agent, AWS Bedrock, FastAPI

  • 점주가 챗봇이 제시하는 매출 수치로 실제 캠페인 예산을 결정하는 서비스 - 숫자 할루시네이션이 곧 잘못된 의사결정
  • Text-to-SQL의 자유 생성 대신, 검증된 쿼리를 파라미터화한 분석 도구 수십 종에 LLM은 라우팅만 담당. 다단계 대화 흐름은 상태 기계로 통제
  • 수치 할루시네이션을 구조적으로 차단하고, 커버리지는 운영 로그 분류가 가리키는 방향으로 점진 확장 (세그먼트 지식 → RAG)
전체 과정 읽기

상황

  • 프랜차이즈 점주/본사 마케터가 점포 데이터를 분석하고 CRM 캠페인을 설계하는 LLM 챗봇 운영/개선
  • 사용자는 데이터 비전문가 - 챗봇이 제시한 매출 수치가 캠페인 예산/타겟 결정의 직접 근거
  • 수치 할루시네이션은 품질 문제가 아니라 잘못된 의사결정으로 직결. 점포 분석이 캠페인 생성의 근거가 되므로 분석 오류가 최종 산출물까지 전파되는 구조
  • 시스템 전반은 AWS 위에서 구동 - LLM은 Bedrock, 데이터/모델 파이프라인은 Glue ETL 등으로 구성

분석 기능 설계 - 사전 정의 도구 + LLM 라우팅

  • 선택지 비교 - Text-to-SQL: 커버리지 넓음, 그러나 잘못된 집계가 그럴듯한 문장으로 포장되는 최악의 실패 모드 / 사전 정의 도구 + 라우팅: 커버리지 제한, 대신 수치 정확성을 구조적으로 보장
  • 분석 니즈가 대상 축(내 점포 → 인근 점포 → 경쟁 브랜드 → 상품 → 캠페인 성과) × 관점 축(추이/시간대/요일/채널/전년 대비)의 유한한 조합으로 수렴함을 확인 → 후자 선택
  • 기존 시나리오를 트리 구조의 분석 레벨로 재설계, 수십 종의 파라미터화된 분석 도구로 시나리오 재구성 및 추가 구현 - 각 tool의 output은 사전 검증/최적화 후 고정
  • 데이터 부재 시 답을 지어내는 대신 명시적 예외로 "데이터 없음" 응답 - 실패조차 설계된 경로로만 발생

대화 흐름 제어 - 팔로업 UI/상태 전이 규칙

  • 매 분석 응답 뒤 팔로업 생성 에이전트가 트리상 인접한 다음 분석 경로를 버튼으로 제시 - 자유 입력 없이도 의도한 분석에 도달하는 경로를 UI 차원에서 보장
  • 캠페인 생성 등 다단계 흐름은 명시적 상태 전이 규칙으로 통제 - LLM의 재량은 각 단계 내 생성 품질에 한정, 흐름의 골격은 결정적(deterministic)으로 유지

운영 로그 기반 검증/개선

  • 일일 사용자 프롬프트 전량을 다층 분류 체계로 직접 분류하며 판정 선례 축적, 세션 이탈 기준을 정의해 "답을 못 얻고 떠나는 질의 유형" 추적
  • 대표 갭 : 타겟 세그먼트 정의/조건 질의: 텍스트 중심 지식이라 정형 도구 추가 대신 지식 베이스 RAG 확장이 갱신 비용/응답 품질 양면에서 유리하다고 판단
  • 분류 작업 자체를 파이프라인으로 이관 중 - LLM API 배치 분류(분류 체계/판정 선례 few-shot 주입, JSON 스키마 강제) 후 분석 마트 적재, 개선 우선순위를 대시보드에서 상시 확인

결과

  • 정형 수치 = 검증된 쿼리 도구, 비정형 지식 = RAG, 대화 흐름 = 상태 기계/팔로업 UI로 책임 분리 - 수치 할루시네이션을 구조적으로 차단하며 커버리지는 운영 데이터 방향으로 점진 확장
  • LLM 제품의 신뢰성은 프롬프트가 아니라 "LLM에게 무엇을 맡기지 않을지"를 정하는 아키텍처에서 나옴
  • 개선 우선순위는 감이 아니라 사용자 로그의 분류 체계에서 나옴

호텔롯데 Upsell 예측 - 예측 모델과 텍스트 키워드 신호의 워크플로우 결합

회귀 예측, NLP(c-TF-IDF, word2vec), Workflow, CDP

  • 롯데호텔 서울의 Upsell 제안 수락률 개선 - 정형 변수 기반 예측만으로는 타겟 정밀도 개선 여지가 정체
  • 수락 성공 그룹의 예약 코멘트에서 c-TF-IDF로 특징 키워드를 추출하고, word2vec 유사어 확장으로 키워드 셋을 보강 - 회귀 예측 모델이 선별한 고객군에 이 키워드 셋을 워크플로우 단에서 결합하는 2단 타겟팅 구성
  • Upsell 수락률 12%p 개선
전체 과정 읽기

가설과 텍스트 분석

  • 가설 : 고객이 예약 시 남기는 코멘트(자연어)에 Upsell 수락 성향의 신호가 담겨 있다
  • 기준 1) 특징 키워드 추출 : 수락 성공 그룹과 실패 그룹으로 데이터를 분리하고, 그룹 단위로 텍스트를 묶어 c-TF-IDF를 적용 - 실패 그룹 대비 성공 그룹에서 특징적으로 등장하는 키워드 셋 도출
  • 기준 2) 유사어 확장 : 기존 워크플로우 rule에 포함된 키워드를 도메인 코퍼스로 학습한 word2vec 임베딩 공간에서 코사인 유사도 상위 후보로 확장 - 유사도 분포를 확인해 임계값을 정하고, 추려진 후보를 검토 후 rule에 추가
  • 기법 선택 : 탐색 단계에서 신호의 존재부터 검증하는 것이 목적이었으므로 해석 가능한 키워드 산출물이 나오는 기법을 적용 - 그룹 대표 키워드에는 문서 단위가 아닌 클래스 단위로 계산하는 c-TF-IDF가, 단어 레벨 rule 확장에는 단어 자체가 벡터인 word2vec이 목적에 부합

타겟팅 워크플로우 설계

  • 정형 변수 기반 회귀 예측 모델로 수락 확률 상위 고객군을 선별하고, 여기에 키워드 셋을 워크플로우 단에서 결합해 타겟을 정밀화하는 2단 구성
  • 텍스트 신호를 모델 내부 피처가 아닌 워크플로우 결합으로 설계 - 코멘트가 없는 고객에 대한 결측 처리 부담이 없고, 키워드 셋 갱신 시 모델 재학습이 불필요하며, 현업이 룰을 해석/조정 가능한 구조
  • 결합 구성에 맞춰 예측 모델과 키워드 셋을 전체 튜닝하며 개선 검증

결과

  • 롯데호텔 서울 Upsell 수락률 12%p 개선으로 연결
  • 비정형 신호는 반드시 모델 안에 넣어야 하는 것이 아니라, 데이터 특성과 운영 구조에 맞는 결합 지점을 설계하는 것까지가 모델링이라는 것을 확인

롯데마트 판매량 예측 - 외부영향요인 검증 및 시계열 모델 반영

Time-series(Prophet), 통계 검정, Feature Engineering

  • 내부 데이터만으로 설명되지 않는 판매량 변동 - 외부영향요인 후보는 수십 개, 무엇을 반영할지 통계적 근거가 필요
  • 외부변수 후보를 유형별 통계 검정으로 스크리닝 → 차원 축소로 예비 변수 10개 내외 압축 → Prophet 시계열 모델에서 하나씩 추가/제거하며 기여 검증
  • 외부변수 반영 시 예측 성능 최대 30%p 개선 입증
전체 과정 읽기

문제 정의

  • 내부 요인만으로 설명되지 않는 판매량 변동을 외부영향요인으로 보완하는 과제 - 후보 변수가 수십 개에 달해, 실제 기여하는 변수를 통계적 근거로 선별해 반영하는 것이 핵심

외부변수 선별 파이프라인

  • ReAct류 에이전트는 매 단계 "다음 행동 결정(라우팅)"까지 LLM 호출에 의존 - 이 라우팅 추론이 전체 비용의 41~54%를 소모함을 정량적으로 확인
  • 응답 생성 과정을 6개 행동의 MDP로 정형화하고, 라우팅 판단만 경량 Double DQN 정책으로 대체 - LLM은 각 단계의 생성 품질에만 사용
  • Bedrock 실환경에서 응답 품질 0.793을 질의당 $0.0055로 달성 - LLM 라우터(ReAct-Opus: 0.696, $0.0131) 대비 더 높은 품질을 절반 이하 비용으로

문제 정의

  • 산업 설비 예지보전 도메인의 질의응답 에이전트 대상 - ReAct 방식은 매 단계 "다음에 뭘 할지"를 LLM에게 다시 묻는 구조
  • 도구 실행 비용보다 라우팅 고민 비용이 더 큰 역전 발생 - 측정 결과 라우팅 추론이 전체 비용의 41~54%
  • 반복적 산업 질의 환경에서는 라우팅 판단의 상당수가 패턴화 가능하다는 가설에서 출발

방법

  • 응답 생성 과정을 Query / Retrieve / Verify / AskBack / Diagnose / Respond 6개 행동의 MDP로 정형화
  • Double DQN 정책으로 질의 유형별 최적 행동 경로 학습
  • 설비 진단 요소로 CWRU 베어링 진동 데이터셋 + 1D-CNN 분류기 결합, Text-to-SQL 등 실제 도구 호출을 포함한 파이프라인 구현

검증

  • Phase 1 : 통제 시뮬레이션: 9개 질의 유형/147개 질의셋 × 6개 비교 정책(고정 경로, 규칙 기반, 지도학습 분류기, Contextual Bandit 등) × 5개 시드 → Strict Accuracy 0.841
  • Phase 2 : AWS Bedrock 실제 LLM 환경에서 응답 품질과 비용 동시 측정

결과

  • 품질 0.793을 질의당 $0.0055로 달성 - ReAct-Opus(0.696, $0.0131)/ReAct-Sonnet(0.683, $0.0110) 대비 더 높은 품질을 절반 이하의 비용으로
  • 결론은 롯데GRS 챗봇 케이스와 같은 방향 - 반복 가능한 판단은 LLM 밖으로 빼는 것이 품질/비용 양쪽에 유리
  • 이 아이디어를 B2C 캠페인 도메인으로 확장한 것이 학회 포스터 연구(Contextual Bandit 라우터, 장려상)
